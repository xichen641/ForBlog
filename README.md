# ForBlog

[English](README.en.md) · [下载插件](https://github.com/xichen641/ForBlog/releases) · [更新记录](CHANGELOG.md) · [反馈问题](https://github.com/xichen641/ForBlog/issues)

将 Obsidian 公开笔记、图片和 PDF 增量同步到本地 Hexo，再通过 Git 发布静态站点。桌面端插件，使用 TypeScript 开发；不依赖 Shell commands，也不需要在笔记中写终端命令。

支持发布属性模板、双链和附件转换、本地预览、归档/分类管理、批量下架，以及单篇/批量切换公开与隐藏。下架保留 Obsidian 原稿。

## 环境与兼容性

| 项目 | 要求与验证范围 |
| --- | --- |
| Obsidian | 桌面端 1.14.4 或更高；0.3.0 将原先未经验证的 1.5.0 下限收紧至实际验收版本 |
| 操作系统 | Windows、macOS Apple Silicon 已进行真实窗口验收；macOS 完整自动测试 65 项通过；Linux / Intel Mac 尚未验收；不支持移动端 |
| Node.js / Git | 电脑上预先安装 Node.js 20+ 和 Git，插件不会自动安装依赖 |
| Hexo | 已初始化并安装依赖的本地博客；集成测试使用 Hexo 7.3.0、Fluid 1.9.8 |
| 博客布局 | `source_dir: source`、`public_dir: public`，单个 Git 部署仓库 |

Node.js 要求指用于构建博客的外部程序；插件本身运行在 Obsidian 内置的桌面运行时。插件当前界面为中文。

## 安装与首次使用

目前可通过 GitHub Release 手动安装。发布 Release 不代表已通过 Obsidian 社区审核。

1. 打开 [0.3.1 Release](https://github.com/xichen641/ForBlog/releases/tag/0.3.1)，下载 `main.js`、`manifest.json`、`styles.css` 三个附件。
2. 将三个文件放入目标 Vault 的 `.obsidian/plugins/forblog/`；也可以解压 Release 中的 `forblog-0.3.1.zip`，将里面的 `forblog` 文件夹放入 `.obsidian/plugins/`。
3. 在 **设置 → 第三方插件** 中启用 ForBlog，填写下面的博客目录、网址和程序路径。

升级时先禁用插件，只替换三个安装文件，再启用；保留 `data.json`，已有设置会继续沿用。首次使用建议先执行预览，确认后再发布。

从源码构建：

```powershell
git clone https://github.com/xichen641/ForBlog.git
cd ForBlog
npm ci
npm run check
npm run package
npm run validate:release -- 0.3.1
```

生成的 `dist/forblog/` 是可直接安装的插件文件夹，包含 `main.js`、`manifest.json` 和 `styles.css`。先在独立的测试 Vault 安装和验证：

```powershell
npm run install:local -- "D:\你的测试Vault"
```

该命令只复制插件文件，不自动启用插件，也不会修改笔记。在 Obsidian 的 **设置 → 第三方插件** 中启用 ForBlog。也可以手动将 `dist/forblog` 复制到目标 Vault 的 `.obsidian/plugins/forblog`。

插件设置建议值（根据你电脑的实际路径填写）：

| 字段 | 示例 | 用途 |
| --- | --- | --- |
| Hexo 博客目录 | `D:\Blogs\Hexo` | 包含 `_config.yml`、`source`、`node_modules` 的目录；首次安装默认留空 |
| 博客网址 | `https://your-name.github.io` | 可覆盖 Hexo `url`；项目站点需要包含子路径 |
| Node.js 程序 | `D:\nodejs\node.exe` | 运行博客本地安装的 Hexo |
| Git 程序 | `D:\Git\cmd\git.exe` | 使用现有 SSH 或 Git 凭据管理器认证 |
| 预览端口 | `4000` | 仅监听 `127.0.0.1` |

### macOS 配置

在终端执行 `command -v node` 和 `command -v git`，将各自输出的绝对路径填入插件设置。通过 Dock 启动的 Obsidian 可能没有终端中的 PATH，尤其是通过 nvm 安装的 Node.js；此时仅填写 `node` 可能无法启动构建。博客目录填写 Mac 上包含 `_config.yml` 的实际绝对路径。

Mac 上用 `Cmd+P` 打开命令面板。源码安装示例：

```sh
npm ci
npm run check
npm run package
npm run install:local -- "/Users/你的用户名/测试 Vault"
```

本次 macOS 测试范围、发现的问题和桌面验收状态见 [macOS 验收记录](docs/macos-acceptance.md)。

Mac 适配修复包含在 0.3.1 中；旧的 0.3.0 安装包不包含这些修复。

博客 `_config.yml` 的部署配置示例：

```yaml
deploy:
  type: git
  repo: git@github.com:your-name/your-name.github.io.git
  branch: main
```

首次使用时，在 Obsidian 打开普通 Markdown 笔记，按 `Ctrl+P` 直接执行 **ForBlog: 预览当前笔记（不推送）** 或 **发布当前笔记（增量）**。缺少有效发布属性时，插件会自动打开预填模板：标题取笔记名，生成可用的网址名称和固定 ID，填入发布日期，分类默认取所在文件夹。

你可以修改后点击 **保存并继续预览/发布**，插件会写入 Front Matter 并继续原操作。关闭窗口或取消不会写入属性，也不会发布。已有有效属性的笔记直接执行原操作。单篇检查、仅同步、侧边栏和右键发布也使用相同流程；批量发布仍只选择已明确标记公开的笔记。

需要单独修改属性时，仍可执行 **ForBlog: 设置当前笔记的发布属性**。已导出文章的 ID 和网址保持固定。

可以在快捷键设置中绑定这些命令。侧边栏发送按钮、笔记右键菜单也可以发布当前笔记。

## 笔记格式

插件的发布属性界面会生成下面的 YAML；也可以手动填写：

```yaml
---
title: CLIP-ReID 学习笔记
date: "2026-10-15T10:00:00+08:00"
tags:
  - ReID
  - CLIP
categories:
  - 论文阅读
blog_publish: true
blog_id: reid-001
blog_slug: clip-reid
---
```

- `blog_publish` 必须显式为 `true`；缺省或 `false` 的笔记不会被批量发布。批量发现使用顶层 `blog_publish: true` 写法。
- `blog_id` 是固定文章身份，界面自动生成 UUID。中文笔记自动生成 `post-<ID前8位>` 形式的有效网址名称，可在首次导出前修改。标题、文件名和笔记所在目录可以更改；请保留这个 ID。
- `blog_slug` 决定 `/posts/clip-reid/` 这样的固定网址，首次导出后锁定。如需改变，先处理引用并下架旧文章。
- `date` 是首次发布时间，`updated` 可选。未填写 `updated` 时，只在公开内容变化时更新，重复同步不会刷新时间。
- `tags`、`categories` 使用字符串数组；分类按 Hexo 层级解释。
- 导出只保留标题、时间、标签、分类和插件控制的渲染字段。其他 Front Matter 不进入博客文章。

发布操作使用打开编辑器的内容快照。保存发布属性使用 Obsidian 官方的 Front Matter API，不整体重写正文。

保存模板后会从刚保存的笔记重新创建发布快照，避免编辑器或 MetadataCache 尚未刷新时再次报“未设置有效的发布属性”。

## 命令

| 命令 | 行为 |
| --- | --- |
| 设置当前笔记的发布属性 | 配置公开标记、固定身份和文章信息 |
| 检查当前笔记的发布变更 | 只检查；不写博客，不构建、不推送 |
| 仅同步当前笔记到 Hexo | 导出 Markdown 和附件；不构建、不推送 |
| 预览当前笔记 | 增量导出并构建，通过本地 HTTP 服务打开实际 Hexo 页面；不推送 |
| 发布当前笔记 | 导出该笔记，构建站点，差异同步并推送 |
| 发布所有修改的公开笔记 | 扫描公开笔记，只写入有变化的文章和附件 |
| 完整重建并发布博客 | 对已有 Hexo 内容清理缓存、完整构建并部署；不隐式导出其他笔记 |
| 重试推送已同步的博客内容 | 构建当前已导出快照（如需要），重试 Git 发布 |
| 打开当前笔记的博客页面 | 使用成功推送记录中的固定网址 |
| 下架当前笔记 | 确认后移除对应导出文件、关闭笔记发布标记，再构建和部署 |
| 管理博客文章（批量下架） | 打开文章管理页，统一列出 ForBlog 和原有 Hexo 文章，勾选确认后批量下架 |
| 停止博客预览服务 | 关闭本地预览服务 |

下架不会删除 Obsidian 原稿或原始附件。其他已导出文章若有对目标文章的链接，会要求先解除链接并同步这些文章，避免下架后留下断链。关闭 `blog_publish` 或删除原稿只停止同步，不自动下架线上文章。

## 管理已发布文章与批量下架

按 `Ctrl+P` 执行 **ForBlog：管理博客文章（批量下架）**，或点击左侧工具栏的文章管理图标；插件设置页也提供入口。管理页独立打开，可搜索标题/分类/路径、按来源筛选、逐篇勾选或全选当前筛选结果。

顶部 **归档 / 分类** 可直接切换：

- **按博客归档**：按文章日期的年份、月份分组，时间倒序排列；没有有效日期的文章放在「日期未知」。
- **按分类**：读取文章的 Hexo `categories`（兼容 `category`）展示父子分类树；普通数组表示一条分类层级，嵌套数组表示多个分类，没有分类的文章放在「未分类」。

分组可折叠、展开，也可以一键勾选整年、整月或某个分类及其子分类中的筛选结果。切换展示方式和筛选时保留已选文章；多分类文章可能在多个分组出现，但只计数一次，批量下架确认页也只出现一次。「全选当前筛选结果」包含折叠分组中的匹配文章，工具栏的「取消选择」会清除全部选择。

页面默认显示紧凑的标题、来源、可见性和日期，点击文章标题可展开博客源码和 Obsidian 原笔记路径。选中文章后出现批量操作栏。搜索支持标题、分类和路径，搜索时自动展开匹配分组。窄面板会改成标题加元信息的两行布局，配色跟随当前 Obsidian 主题。

列表包含当前博客 `source/_posts`（含子目录）中的 ForBlog 和原有 Hexo 文章。可见性显示「公开」或「隐藏」，未完成的修改标注「待部署」。ForBlog 的推送状态可在可见性按钮提示中查看，首次未部署的文章标注「待发布」。About、Links 等独立页面不作为文章处理。

### 修改可见性

点击单篇文章的 **公开 / 隐藏** 按钮，或勾选多篇后点击 **修改可见性**，选择目标状态，再点击 **保存并部署**。确认前会列出所选文章，取消不会写入文件或执行部署；选择与当前状态一致时不能重复保存。

- **公开**：生成文章页面，并出现在博客列表中。
- **隐藏**：写入 Hexo `published: false`，完整重建并部署后不再生成文章页面，也不显示在首页、归档、分类和搜索中。文章源码仍保留在原位置，可再次设为公开。

两种操作都保留 Obsidian 原稿及 `blog_publish` 标记。ForBlog 会持久保存隐藏状态，后续单篇/批量同步仍保持隐藏；手动给已导出稿设置 `published: false` 后同步，也会保留该状态。ForBlog 独占导出附件会从隐藏文章的公开产物中移除，保留本地源码附件；原 Hexo 共享附件不删除。

修改前会校验当前源码和文章属性，属性损坏或源码缺失时禁用可见性编辑。其他公开 ForBlog 文章仍链接到目标文章时，需先修改链接并同步，或将引用文章一同隐藏；恢复公开时也会检查指向隐藏文章的链接。部署失败保留本地可见性和待部署记录，点击 **重试部署变更** 可继续。

点击 **下架所选** 后，确认页会逐篇列出标题和路径。确认后仅将所选文章的博客源码及 ForBlog 独占导出附件移入 `.forblog/trash/<批次>/`，再清理构建缓存，统一构建、提交和部署一次。原 Hexo 文章的共享附件保留。备份位于构建目录外，不会发布到网站。单篇「下架当前笔记」也使用同一备份机制。

Obsidian 原稿和原始附件保留，只将对应 ForBlog 原稿的 `blog_publish` 改为 `false`；原稿移动后按固定文章 ID 查找。下架记录也会阻止后续批量发布重新创建文章。需要重新发布时，打开原笔记执行「发布当前笔记」并确认发布属性；旧 Hexo 文章可以从备份按原路径恢复后完整重建部署。

列表打开后若文章发生变化，会要求刷新重选。其他未选文章仍引用所选 ForBlog 文章时，会阻止整批操作；可先解除引用，或将引用文章一同选中下架。部署失败会保留备份和待部署记录，页面提供 **重试部署变更**，也可使用现有的重试发布命令。

## 增量更新如何工作

插件使用 SHA-256 对公开正文、公开属性、转换后的链接、附件内容和转换器版本计算指纹，不只依赖文件修改时间。只改图片也会识别为文章变化；只改未导出的私有属性不会重新发布。

1. 先完整检查本次选中的笔记和附件，再开始写入导出文件。
2. 对生成的 Markdown 和附件逐一比较字节，内容一致时不写文件，保留修改时间。
3. 普通发布保留 Hexo `db.json` 与 `public` 缓存。Hexo 仍运行站点生成器，未变化的文件跳过写入；首页、归档、标签和搜索索引按实际影响更新。
4. 生成文件差异同步到专用 Git 工作目录，仅写入和删除变化文件。无产物变化就不创建新提交、不推送。
5. Git 推送成功后才更新 `published` 指纹。推送失败保留已导出内容和待推送提交，可以重试。

全局 Hexo 配置、依赖锁文件、插件使用的博客网址或本地 `themes/` 改变时，触发完整重建。通过 npm 安装的主题版本由依赖锁文件反映；手工修改 `node_modules`、博客 `scripts/` 或其他未跟踪构建输入后，请执行完整重建。

部署始终维护完整站点快照。GitHub Pages 平台仍按站点版本发布，插件不承诺平台内部只部署一篇文章。

## 文件与发布记录

```text
Hexo 博客目录/
├─ source/
│  ├─ _posts/forblog/<blog_id>.md
│  └─ assets/forblog/<blog_id>/<内容哈希>-<附件文件名>
└─ .forblog/
   ├─ manifest.json    # 已导出/已推送指纹、链接和附件归属
   ├─ hexo.yml         # 构建时的网址覆盖配置，不修改原 _config.yml
   ├─ publish.lock     # 跨窗口发布锁
   └─ deploy/          # 独立 Git 工作目录，正常快进推送
```

请保留 `.forblog/manifest.json`，丢失它就会失去文章归属和增量记录。若将 Hexo 源码加入 Git，建议忽略 `.forblog/deploy/`、`.forblog/publish.lock` 和 `.forblog/hexo.yml`，并自行决定是否备份 manifest（其中包含本地笔记相对路径）。

首次部署使用 `--depth 1 --filter=blob:none --no-checkout --single-branch --no-tags` 获取最新提交和文件清单，直接用本地 `public` 填充部署内容，避免重复下载旧站点的图片等文件。目标 Git 服务需支持过滤才能省去文件内容下载；不支持时 Git 会提示并回退普通浅克隆。克隆在 `.forblog/deploy-initializing-*` 临时目录进行，成功后再移入 `.forblog/deploy`；失败或取消后清理临时目录，允许直接重试。已有完整部署仓库和推送失败后留下的本地提交会保留，供后续增量部署重试。

构建、检查远端、浅克隆、获取更新、提交和推送分别显示进度，命令输出实时写入日志并过滤颜色控制字符。首次克隆最多等待 300 秒，其余命令默认 180 秒；超时会指出具体阶段。Windows 超时和取消使用 `taskkill /T /F` 终止整个进程树，待终止完成后再报告失败和清理初始化目录。

已有 `hexo-deployer-git` 的 `.deploy_git` 不会被修改；插件使用自己的 `.forblog/deploy`。不要在插件发布过程中同时运行其他部署工具。插件不强制推送，远端分歧会报错；在本地生成的提交身份为 `ForBlog <forblog@localhost>`。

**预览和仅同步会改变博客本地源码/构建产物。下一次部署会发布整个已导出快照，包含此前预览留下的待发布修改。** 这是“同步后预览”的工作方式。若只想检查而不改变博客，使用“检查当前笔记的发布变更”。

## 支持的语法与边界

| 内容 | 首版行为 |
| --- | --- |
| Markdown 标题、代码块、表格 | 保留，交由博客现有渲染器处理 |
| `![[图片.png]]`、`![[图片.png\|600x400]]` | 复制图片并转换为带尺寸的 HTML 图片 |
| 普通/引用式 Markdown 本地图片与附件 | 解析、复制、重写为博客资源地址 |
| `[[文章\|别名]]` | 目标已导出或在本批次中时转换为博客链接 |
| 指向未公开笔记的双链 | 转为显示文字并提示，不隐式公开其他笔记 |
| `![[论文.pdf#page=3]]` | 复制 PDF，生成浏览器原生 iframe 和下载链接；不依赖 PDF.js |
| 音视频附件 | 支持 mp3/ogg/wav/mp4，生成原生播放器 |
| `%%私有注释%%` | 删除正文中的注释，保留代码和公式中的示例；未闭合注释阻止发布 |
| 数学公式、Mermaid | 保留并提示，需要博客自行配置渲染器/主题 |
| 笔记嵌入、标题/块双链、Dataview | 明确报错，先转换为静态内容或整篇文章链接 |
| SVG、Canvas、其他附件类型 | 首版不导出，明确提示不支持 |
| Markdown 中 `/...` 根路径、外部链接 | 视为已有网站地址保留，不从 Vault 复制 |

内部链接解析依赖 Obsidian 的 MetadataCache。首次给新文章建立关联，建议在同一批次发布；已导出文章中的纯文字引用不会因单独发布目标笔记而自动改写，执行“发布所有修改的公开笔记”会重新计算链接依赖。

插件不会将整个 Vault 或整个附件目录复制进博客。路径越界、托管目录符号链接、缺失附件、身份/网址冲突以及覆盖非托管文章都会阻止发布。Obsidian 原稿中的普通文字和原生 HTML 仍按作者提供的公开内容导出。

npm run dev      # 监听源码并重新打包

自动测试覆盖转换、附件独立变化、无变化时修改时间不变、笔记移动、错误预检查、下架、文件差异同步、真实本地 Git 推送/拒绝/重试，以及真实 Hexo 构建和本地 HTTP 预览。所有 Git 测试仅使用临时本地裸仓库，不推送 GitHub。

另有真实 Fluid 主题渲染检查，以及对打包后插件的模拟 Obsidian API 加载、12 个命令注册、发布属性编辑、管理页筛选/选择/确认、保留原稿和防止下架文章重新批量发布的检查。模拟 API 检查不替代真实 Obsidian 窗口中的验收。

本地检查通过不等同于已验证 Obsidian 实际加载、真实 GitHub 认证或 GitHub Pages 上线。启用插件后，先用测试文章预览，再执行首次真实发布。

## 数据访问、网络与权限

- 插件通过 Obsidian API 读取笔记和所引用附件；批量发现会读取 Markdown 笔记以查找显式发布标记。保存发布属性、下架等明确操作可能修改笔记 Front Matter，保留原稿正文和原始附件。
- 插件会访问 Vault 以外由你填写的 Hexo 目录，读取配置、写入导出文章和附件，并在 `.forblog` 内保存状态、部署副本及下架备份。
- 本地构建启动已安装的 Node.js / Hexo，部署启动 Git。Hexo 及其主题、插件来自你现有的博客环境；ForBlog 不自动下载或安装它们。
- Git 只连接你在博客中配置的远端，用于读取部署分支和推送，沿用系统 SSH 或凭据管理器。插件没有遥测、独立账号或自营远程服务，不提供访问令牌存储字段；认证信息不要放进仓库 URL。插件配置保存在本地 `data.json`。
- 预览服务只监听 `127.0.0.1`；浏览器打开预览时，主题或文章配置的外链资源仍可能访问外部网站。打开博客文章会访问配置的博客域名。
- ForBlog 无需付费或注册；Git 托管服务可能要求账号。隐藏或下架不会清除 Git 历史、托管缓存或第三方已保存的副本。
